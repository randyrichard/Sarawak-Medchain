# Usability review, 12–13 October 2026

The brief: check the SafeChain web app thoroughly for whether it is suitable and easy to use,
and miss nothing, above all what leaves people confused or lost.

So the app was used the way a new starter uses it, on a desk screen and a phone, for every
role, asking the questions people ask when they are stuck: *how do I get back*, *where did my
work go*, *why won't it save*, *where are my records*, *did that save*, and *what does this
mean*. Following those turned up one more: *did what I typed actually stick?* On a real server,
for corrective actions, some of it did not.

Everything below marked **Fixed** has a test that fails without the fix, was re-checked in a
browser against the real API or the public demo build, or both.

## What changed

| People ask | Before | Now |
|---|---|---|
| How do I get back? | An open record lived only in the page's memory, so the browser's Back button, the only one an Android phone has, left the list for the page before it | Back closes the record and stays on the list; Close leaves no extra history; a refresh keeps it open; a link can open it. Actions, Permits, Assets, Audits, Visitors, Employees, Contractors (workers and firms), Training and Toolbox |
| Where did my work go? | A click outside a dialog, Esc or the X threw away everything typed in it | It asks "Discard what you've entered?" (**Keep Editing** / **Discard**) once anything has been typed or picked. Cancel, and dialogs nothing was typed into, close at once |
| Why won't it save? | Save buttons stayed grey until the form was right and said nothing about why ("Fire" was too short for a near miss, written nowhere). Other forms sent anyway, and on a server came back with "String must contain at least 1 character(s)", naming no field, at the foot of a long scrolling form | Forms that create or change records can always be sent. If something is missing, each field says what it needs, under the field, and the screen goes to the first one: 31 forms, including every one that creates something. Buttons still greyed out say why on the button ("Answer 3 More Items") or sit beside an empty comment box |
| Where are my records? | A search that found nothing said "No audits in scope - plan one to get started", showed five columns each reading "Empty", or "no live permits in this scope", with no way to undo the search | It quotes the search back, says what else is narrowing the list, offers **Clear Filters**, and says when only one site is being shown, with **Show All Sites** |
| Did that save? | The dialog closed and nothing else happened; the new record was somewhere in a long list | A new corrective action, asset or audit opens; a scheduled training session is confirmed by its number, course and date |
| What does this mean? | JSA, LEL, LOTO, SCBA, IC, MFA, CIMAH, HIRARC and others were used and never explained; "Save RCA"; the no-access page said a role lacked "the visitors:view permission" | The Help glossary explains every abbreviation that appears on a screen (37 terms, checked by a test both ways: each abbreviation it explains is on a screen). "Save Analysis". The no-access page says what the page needs in words ("See visitors on site") |
| Is this broken? (public demo) | HSE Performance said "Could not load HSE performance" in red, with a Try Again button that could only fail again | "Not in this demo", and the reason, with nothing to retry |

Words: the app is for Malaysia, so British spelling throughout (Organisation, Security
Centre, Catalogue, programmes, Colour); the 404 page offers **Home**, as the menu calls it;
names built in code are in Title Case with real plurals ("Upload 6 Photos", not "Upload
Photo(s)"); the incident wizard's first step has **Cancel** rather than a Back that could
not be pressed.

## Found on the way, and fixed

| # | Finding | Who it hit | Status |
|---|---|---|---|
| 1 | **On a server, managing corrective actions saved less than it showed.** Edit (owner, priority, details) and the bulk **Reassign** saved only the due date: the old owner kept the work, the new one was never told, and the screen reported success. New Corrective Action dropped its details and its "evidence required" rule, so an action raised that way could close on a note; an investigation's actions dropped the rule too. The register then said every action needed a file to close, including those that did not. | HSE managers, administrators and action owners on a real deployment | **Fixed.** The server takes owner, priority and details (managers only, like the target date), tells the new owner and raises `action.assigned`; the evidence rule is kept; the web sends all of it and reads it back. Tests: `api/clientActions.test.ts`; `actionOwner.integration.test.ts` (reassigning, the manager-only rule, no notice for an unchanged owner, the rule kept). Checked in a browser: a reassignment and a priority change survive a reload, and the database row and both notices match. |
| 2 | **A corrective action raised outside an investigation told nobody.** The button says "Create & Assign"; the owner learnt of it only by opening the register. | Action owners | **Fixed.** The owner is told, as an investigation's action owner is. |
| 3 | **Forms asked for what the server cannot keep.** An action's department, named reviewer, source, the root cause it answers and progress in quarters are kept by the demo's own store only. On a server they were asked for and dropped: a reviewer was named who never heard of it, and progress set to 75% went back to 50%. | Managers on a real deployment | **Fixed.** Not asked for on a server; the demo still asks, because it keeps them. Keeping them on a server would need new columns, which is a product decision (see Still open). |
| 4 | **Completing an action: "Completion note (optional)".** The server always wants a note saying what was done, so the optional note was refused. | Action owners | **Fixed.** Labelled as required; the demo follows the server's rule. |
| 5 | **Forms that guessed.** A course with no duration went in as one hour, and one with no delivery mode as "physical"; more people could be enrolled than there were seats, refused only by the server. | Training coordinators | **Fixed.** Asked, not guessed; too many people for the seats is said before sending. Test: `app/createForms.dom.test.tsx`. |
| 6 | **"SES-507 scheduled: Safety Induction, 05 Nov, 12:00 am."** A session is booked for a day, not a time; in Malaysia the same code would have said 8:00 am. | Training coordinators | **Fixed.** The day only. |
| 7 | **Selections a screen reader could not hear.** The audit team, session participants and course departments are toggles whose state was colour alone. A training session's site was shown by its code ("KCH"). | Screen-reader users; anyone new | **Fixed.** Each toggle reports pressed or not; the site is named in full. |

## Corrected afterwards, 13 October

The demo crawl above followed links from one page and never opened Home, record panels or
tabs. On a phone the public demo's **Home** showed "needs the SafeChain server" in red, twice,
over "Needs Attention · 0 items", and the notifications panel ran 110px off the left edge.
Visitors, Employees, Contractors, Reports, the incident and equipment boards, two incident
tabs and the asset and permit records showed the same message as a red alarm.

- Home in the demo now counts from the demo's own records, by the server's rules, each
  figure through the filter its link opens. Visitors, scheduled reports and calibration are
  left off Home in the demo, with one line saying so. Tests: `api/mock/overview.test.ts`,
  `api/clientDashboard.test.ts`.
- A part the demo does not include says "Not in this demo" calmly (`ErrorAlert`,
  `NotInDemo`); with a server the same failure is still an alarm. Tests:
  `ErrorState.dom.test.tsx`, `VisitorsPage.dom.test.tsx`, `AssetDrawer.dom.test.tsx`.
- Menus stay on screen on a phone, and `npm run audit:mobile` now checks every top-bar menu.
- Needs Attention named stages by their column values ("rca"), called an open incident
  "18 days overdue", and said "Expires in 1 hours", "Awaiting submitted · raised 0 day(s)
  ago" and UTC times. Fixed on the server and in the demo alike.

Checked by opening every page, every tab and the first record of each list in the demo
build, on a desktop and an iPhone SE.

## Still open

- **The public demo's address** still carries the account's email name. The code now names
  the Worker `safechain`; the Worker itself and the account's `workers.dev` subdomain are
  renamed in the Cloudflare dashboard (`CLOUDFLARE.md`, "The public demo"). An address that
  is only "safechain" needs a domain of its own.
- **Action department, reviewer, source and linked cause on a server.** Not asked for any
  more, because there is nowhere to keep them. Whether a real workspace needs them is worth
  asking the pilot customers before adding columns.
- **API clients still get the server's own validation wording** for a few create routes
  ("String must contain at least 1 character(s)"). Every form in the app now checks first, so
  people do not see it; integrations would.
- A real iPhone in Safari before an important release (`GO_LIVE.md` §3). The browsers here
  are Chromium at phone sizes.
