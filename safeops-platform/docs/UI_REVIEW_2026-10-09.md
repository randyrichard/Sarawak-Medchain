# Interface review, 9–10 October 2026

The brief: too many symbols, and the product should look professional and be easy for
somebody new to the job. Doing that meant following every link and button a new starter
would press, and several of them did not do what they said. Those are listed below with the
interface changes, because a newcomer meets them first.

Everything marked **Fixed** has a test that fails without the fix, was re-checked in a
browser, or both.

## What changed

| Area | Before | Now |
|---|---|---|
| Icons | 617 on the thirteen busiest pages: every menu row, tab, tile, heading, button, badge and status pill carried one | **164**. 78 of them are the logo and the five top-bar controls repeated on each page. The rest are controls (close, sort, expand, search) or alarms. Rules in `web/src/components/ui/README.md` |
| Buttons | An icon beside every label | `Button` and `LinkButton` show an icon only when there are no words; the loading spinner still shows |
| Status pills | Icon and colour | Words with a coloured edge |
| Names | Menu said "Corrective actions", page said "CAPA"; "Mission Control", "Workforce", Title Case | Each page title is its menu label, in sentence case. "Home", "Employees", "Report incident" |
| Subtitles | Slogans ("Audit-ready every day…") | What the page is for, in a sentence a new starter can act on |
| Help | None | **Help** at the foot of the menu and in the account menu: what SafeChain is, a guide for the reader's own role, step-by-step instructions naming the buttons to press, a glossary (near miss, LTI, TRIR, DOSH, PPE…), and the emergency first: act, then report |
| First visit | A page of figures | Everyone but the administrator gets **New to SafeChain? Start here.** on Home: their role's first three jobs, each a link, and the guide. Dismissible. The administrator keeps the setup checklist |

The guides are checked like code (`features/help/guides.test.ts`): every link opens for the
role it is written for, every button name they tell people to press still exists on a screen,
and the permit-approval guide is offered to exactly the roles the server lets sign.

## Found on the way, and fixed

| # | Finding | Who it hit | Status |
|---|---|---|---|
| 1 | **Notifications never opened what they were about.** The bell and the Notifications page only marked a notification read; the link it carried was ignored. "Corrective action assigned: CA-419" gave the person it was assigned to no way to the action. | Everyone | **Fixed.** A notification opens its record. Only paths inside the app are followed, so a stored link cannot send anybody off-site, and a reminder about a page the reader's role cannot open stays a plain row rather than leading to "you don't have access". Tests: `NotificationsPage.dom.test.tsx`, `links.test.ts`, `nav.test.ts`. Checked in a browser for employee, executive and supervisor: no link on Home, Notifications, Help, Incidents or Permits leads to a refused page. |
| 2 | **Corrective action reminders linked to `/actions/<id>?due=3`, a page that does not exist.** The shape is how the scheduler tells one reminder from the next, so the server keeps it. | Action owners | **Fixed.** That path now opens the action. |
| 3 | **Links opened a list instead of the record.** Search sent `?open=` to Permits, Assets and Audits, which read `permit`, `qr` and nothing; Home's attention list sent `?focus=`; reminders sent `?asset=` and `?cert=`. Seven of eleven link shapes opened the list and left the record to be found by hand. | Everyone | **Fixed.** Each page reads every name it is linked by. A test reads the API's link templates and the pages' source, and fails any link whose page never reads its parameter (`features/dashboard/links.dom.test.tsx`). |
| 4 | **Home's figures opened unfiltered lists.** "Overdue 1" linked to `/actions?due=overdue` and the page reads `bucket`; the same for "Permits awaiting review", "Expected today", "Out of service", "Investigating" and others. | Everyone, from the first page they see | **Fixed.** Home's links are built from each page's own filter types (`lib/links.ts`), so a value a page does not understand no longer compiles. Every figure was followed in a browser and lands filtered, with the filter shown. "Due this week" and "Expiring in 7 days" needed filters of their own and have them. |
| 5 | **Employees could not open the corrective actions assigned to them.** The server lists an employee their own actions and lets them work them, and the page has an employee view, but the route asked for `actions:manage`. The notification led to "You don't have access". | Employees | **Fixed.** A new `actions:view` capability; an employee sees only their own actions and can start and complete them, nothing else. Checked end to end on a phone. |
| 6 | **A permit disappeared once its first reviewer signed.** The approval-chain stages were not counted as live, so the permit left the Live board and "Awaiting approval" (which matched `submitted` alone). The HSE reviewer and area authority who had to sign next could find it only under All. | Permit reviewers | **Fixed.** Both include the chain; "Awaiting approval" covers submitted and every review stage. Test: `permitService` integration test. |
| 7 | **The Corrective actions Analytics tab showed the browser's demo data in a real workspace.** Owner load, sites, departments and the monthly trend came from the sample company; a real workspace showed sample people's names. "Completion rate" was closed against overdue, not verified against all raised as labelled, and the closed total stopped at 500. | Managers reading the tab | **Fixed.** Every panel is counted by the server from the workspace's own actions (`domain/actionPanels.ts`), scoped by role as before. A rate with nothing behind it shows a dash, not 0%. Tests: `actionPanels.test.ts`, `incidentService` integration test. Checked: the owner list now matches the database row for row. |
| 8 | **Home's "Lapsed, not closed" and "Expiring in 7 days" stopped at 10.** They were the lengths of the ten-row attention lists. | Permit desk | **Fixed.** Counted. Test: `dashboardService` integration test (twelve lapsed permits read 12; the old code reads 10). |
| 9 | **Demo data: every finished action was created after it was finished**, so the average close time was −6.2 days | The demo | **Fixed** in the demo data, and a record finished before it was created is left out of the close time rather than averaged in. |

## How it was checked

| Pass | Result |
|---|---|
| Automated | API suite 1,560 tests and web suite 691, both typechecks, the production build, the bundle credential scan, the offline demo build |

| Phones | `npm run audit:mobile` on iPhone SE, iPhone 14 Pro, Pixel 7, Galaxy S8 and iPhone SE landscape, with the Help page added to it: **0 findings** |
| Crawl | Every page, tab, dialog and drawer for employee, supervisor, HSE manager, executive and administrator, on phones and at 1440×900, light and dark: **594 screen states, 0 page errors, 0 accessibility violations** (axe-core, WCAG 2.2 A/AA including contrast) |
